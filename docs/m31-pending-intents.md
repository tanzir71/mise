# M31 — Pending domain actions and original image delivery

A fixed download can finish while newer actions are still offline or have been
accepted after that window. Canonical application now projects every currently
typed command family over the verified base: catalogue, customer/khata, money,
stock, suppliers/invoices, orders/payments/refunds, closing, manual messages,
Inbox, reminder wording, exports, owner settings and frozen shop links.

The projection is tentative. Actual scoped receipt coverage alone distinguishes
visible, absent and later commands. A matching row or audit cannot replace that
proof. Original commands, related IDs, outbox changes and receipts remain intact;
applying a download creates no outgoing echo or invented receipt.

Six server mutation calculations now live in pure shared core modules. Their
server wrappers retain original-JWT ticket admission and service-only completion.
Local projections supply domain facts without inventing a ticket, token, Auth
identity or permission. Complete compound financial records, original source
receipts, reviewed closing fingerprints and undo constraints remain enforced.
Scalar updates retain losing canonical values in the tentative audit; the actual
accepted server audit supplies final ordering and times.

Original Inbox images are reconstructed from the complete queued source, with
exact metadata, ordering and a hash of every byte. Missing or changed originals
retain the action and download. Existing member outlet assignments survive
scalar profile projection. Immutable notes, communications, ledger entries,
stock movements and audits cannot be overwritten through replay.

## Image delivery

Automatic sync now sends complete original image Blobs to the existing private
image service after their metadata command is accepted. The transport pins the
original runtime account and connection before HTTP and after its bounded reply.
Native checks retain the original operator, command source and complete Blob
through completion. No image acknowledgement is manufactured or inserted into
the command receipt list. A lost reply retries the same immutable image; the
existing server completion records one upload audit. Verified canonical upload
metadata avoids sending that image again on later cycles.

Portable backups now validate image-upload audit metadata separately from manual
sorting history. Uploads neither increment nor replace Inbox revisions. Invalid
image references, duplicate confirmations, extra fields and mismatched times are
rejected. Original bytes and manual history remain exportable and recoverable.

Local schema 20, its 34 stores, portable schema 10 and its 21-table allowlist are
unchanged. Connection values and credentials remain outside shop data, queues,
backups, public build variables and source control.
