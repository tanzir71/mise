# Original payment targets

M41 payment review now shows the original order number and customer, khata customer name/nickname, or counter customer and shop. Current links, financial recordings, original undo and removed-link history use retained evidence. Renaming a customer or editing an order later does not change the original display.

Every native receipt still validates its complete Payment history, shared snapshot digests, original financial audit links and immutable credit-ledger prefixes before presenting these labels. The read-only projection reuses that checked reader. Missing or altered originals fail the receipt read; current names never substitute for missing evidence. No schema, stored record, backup format or financial write rule changes.

Order links open the actual order detail. Customer links open the actual customer with the original account currency selected. Counter history has no individual receipt route, so it opens the real counter and keeps the complete original receipt identity, amount and recording time visible in the payment sheet. Metadata associations keep their own original labels and receipt identity after removal. Financial history keeps its original target after undo. Literal labels render as text.

Each installation owns its source clocks, labels, provider setup and backend configuration. This follow-up requires no maintainer account, keys, phone or provider commissioning.
