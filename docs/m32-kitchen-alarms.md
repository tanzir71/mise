# M32 kitchen alarms — in progress

This local increment adds a server alarm worker that prepares scoped order sources, hashes the existing preparation projection and finishes under the normal outlet/order transaction locks. The default warning is two minutes; owner/manager settings can disable it or choose 1–1440 minutes. A changed source, accepted Got it or newer work generation makes an earlier worker observation stale. The new migration and worker remain undeployed.

Due alarms create the existing first-class Inbox `tasks` record with Open order and Copy actions. Private bindings retain the original order, content hash and source revision. Retries cannot create another task or pending notification. System audit events record raising and resolution without inventing a member actor or changing an order, customer message or financial record.

A real current Got it resolves its matching task and cancels pending notifications in the acknowledgement transaction. Historical receipts remain intact. Undoing that acknowledgement can reopen the same content task as another generation. Changed preparation content closes the earlier task and creates a distinct task; disabling warnings or completing/cancelling the order resolves active tasks. Only assigned owner/manager phone accounts can read them, including through direct table RLS.

The existing device reader returns the configured warning period, or `null` when disabled. Configuration changes wake its original scoped cursor. The native screen cache retains disabled warnings through offline reload without a database version change.

Web Push request preparation uses pinned `web-push` 4.0.0 with a per-request VAPID identity, `aes128gcm`, a 30-second TTL, high urgency and a stable task topic. Transport restricts destinations to browser push providers, rejects redirects and aborts after five seconds. Payloads contain scoped notification identifiers; customer text, money, order numbers and credentials are absent. Independent test decryption and signature verification cover the actual library-generated request. Provider subscriptions, per-desk delivery and service-worker presentation are still to be connected.
