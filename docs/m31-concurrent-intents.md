# M31 — Concurrent original domain intents

Two offline devices can act on the same original revision. Reconnecting now
preserves additive order notes and confirmed communications, including the exact
companion record for an explicit manual-message Sent assertion. Each retains its
original command, literal text, related IDs and physical time. The server admits
the action against the actual current order and records its resulting revision;
an exact retry reads the original receipt without appending again.

Nonfinancial order edits and supplier edits use server admission order. Audits
retain the actual losing current values, even when the last admitted device has
an older physical clock. Supplier edits preserve archive state; repeated archive
or restore assertions retain history without replacing the first archive time.
Record update clocks remain monotonic. Duplicate nonfinancial status assertions
preserve the actual last transition identity and time, so its existing undo stays
available. A different status must still be a legal next transition.

Inbox classification and archive sets apply only their selected field to the
current source. Identical sets acknowledge a genuine no-op without inserting a
manual revision. Complete immutable source fields, original image metadata and
every original image byte survive pending projection, delivery and download.

Future revisions, colliding original new-line identities, stale financial
reviews, changed source receipts, invalid lifecycle transitions and expired undo
remain guarded. Hand-off attempts retain their own strict generation/progress
revision. The server still checks current membership, outlet, ticket, normalized
intent hash, source snapshot and complete completion values. The migration
replaces seven private function bodies and preserves their ownership, grants and
empty search paths; it adds no tables, public grants or policies.

A frozen download may predate an already completed local action by hours.
Tentative replay uses the immutable original queue action time and physical
command time alongside the observed window time. This is a deterministic local
projection, never a server clock, permission or receipt. Server admission keeps
its actual clock and expiry rules. Original queue entries, commands and receipts
remain unchanged; only genuine fixed-window coverage proves inclusion.

## Verification

SQL-backed domain checks cover additive concurrent actors, server ordering with
older device clocks, losing-value audits, duplicate status/archive assertions,
future revisions, strict financial reviews and complete Inbox manual history.
Native IndexedDB checks retain original queues over remote notes/classification
and a download frozen more than five minutes before later actions.

Two native-browser scenarios run the actual application, HTTP handlers, scoped
Postgres roles and all migrations. The first pulls another device's accepted
changes before sending pending originals, then compares complete records across
both devices and verifies an exact retry. The second uses the rebuilt app's
automatic sync and outlet event hints without manual delivery calls. Auth,
Realtime and object-storage adapters in these local fixtures are explicitly
synthetic; they do not prove genuine hosted phone OTP or signed-user acceptance.

[Local verification evidence](m31-concurrent-intents-local.json) records 2,429
passing unit tests, 434 complete browser cases, 14 root-path cases and 212 fresh
visual comparisons with zero overflow. Both deployment bases, lint, TypeScript
and all 270 exports pass. The single reviewed migration is applied; commands
version 20 matches its reviewed bundle and retains JWT verification. A locally
verified, rollback-only 13-command SQL-role proof also passes on the hosted
database, including an original communication at revision 2 admitted as revision
4. Every synthetic Auth/shop/ticket row is rolled back. Five real unauthenticated
HTTP probes return 401; neither proof substitutes for genuine signed-user acceptance.
