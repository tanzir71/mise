# Native payment backend authority

The M41 `native-payment` Edge function re-evaluates an actual retained native invocation against current authenticated outlet records. It keeps the native protocol separate from the older M37 observed-payment protocol. This backend increment does not yet connect the app outbox, initial upload, canonical reconciliation or ordinary-backup archive; their existing fences remain.

The request contains the original version-one command and its checked resulting Payment hash. Admission verifies the real phone Auth identity, active member, role and outlet assignment before reading the bounded body. Preparation binds that identity, original request, current complete context and admission time to an expiring private ticket. Completion rechecks live authority and the context under outlet locks. A context-only race may reprepare the same original request; a changed native result requires a fresh human review. Completed retries return the immutable original receipt before attempting another financial transition.

Capture, edit, match, unmatch, set-aside, reopen, new received-money recording and original undo use the same strict native executor as local actions. The backend writes the genuine order/sale/khata child identities and original action/invocation/evidence companions in one transaction. Matching an existing receipt changes metadata only. An incomplete invocation, wrong amount, changed immutable source or missing companion rolls back the entire write. The original financial undo must pass current dependencies and the ten-minute window against both the native posting clock and persisted server recording receipt. A device clock cannot extend that window.

Four private, forced-RLS tables retain native state, literal audits, immutable request receipts and short-lived tickets. Client roles have no direct table access, authenticated callers can only admit/prepare, and service-only completion runs through an invoker wrapper. Private definers use an empty search path. Native audit IDs are reserved against legacy audit reuse under a shared transaction lock. Existing public observed-payment rows, legacy cloud DTOs and the twenty-two-table ordinary backup format are unchanged.

Native text remains complete, including NULs and lone UTF-16 surrogates represented in JSON. SQL traverses opaque string tokens instead of decoding user text through jsonb; canonical comparison reconstructs the literal JSON. Safe IDs, enums and clocks are decoded separately. Scoped preparation includes the complete ledger and only relevant outlet customers. The backend rejects an oversized complete context rather than silently clipping it. The original 5,000-charge corpus and million-code-unit note cover three collections, exact retries and original undos. Bounded archive transport is still required before app integration.

Each installation configures its own allowed origins, backend URL, public API key and private service key through the existing [private server environment template](../supabase/functions/.env.example). No new provider account, phone number or credential is requested from the maintainer. Service credentials never enter browser code or an HTTP receipt. Empty configuration returns an unavailable response with the manual-money path. The exact deployable bundle is exercised against local PostgreSQL; no hosted migration or function has been deployed.

The paymentText preview remains off by default. Native schema 29 and ordinary schema 13 remain unchanged. [Durable local originals](payment-original-archive.md) now add complete ordinary backup/restore. The [SDK/native-bound original-copy controller](payment-original-copy-binding.md) now covers authenticated archive transport, strict readback and known-copy recovery. Remaining M41 work includes original-versus-canonical outcome receipts, app outbox delivery, initial native-history registration without reposting old money, and lossless canonical/backup projection. The backend increment introduced native schema 29; retained originals now use native schema 30. Workflow runs, publication, service/migration deployment, provider commissioning and tags remain held.
