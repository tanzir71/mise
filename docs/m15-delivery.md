# M15 · Stock and night count

The Stock UI connects the audited foundation to item editing, inline physical-count steppers, Low/To order/category filters, search, movement history, archive/restore, supplier contacts and grouped order drafts. Items require an explicit opening count and remain separate from the sale catalogue. Changing On hand records a physical count; Received, Used and Waste are explicit manual actions.

Quick updates freeze their before/after values and revisions when reviewed. Quantities remain editable, invalid clauses prevent saving a valid subset, and a stale save requires an explicit review of current stock. Optional browser speech fills a draft only; it never writes stock and retains three decimal places. Typing and the keypad remain available offline. Oversized pack-rounded recommendations stay visible as an editable pack-size issue.

Night count follows one item at a time, with a large number field, 3×4 keypad, explicit pack/unit selection, Skip and Next. Its summary shows each original amount, physical count and variance, including zero differences. Apply writes one atomic count batch; skipped items remain untouched. Another tab's stock change blocks Apply until those items are recounted. Summary rows can reopen an item for editing.

Supplier drafts use the current target deficit rounded to pack size, grouped by supplier. Text follows the shop's message languages and long lists split into complete parts. The review sheet provides WhatsApp, Copy, a manual clipboard fallback and explicit Sent. Repeated taps record one completion; History retains the recipient/text snapshot and supports correction. Sending never receives stock or creates a purchase or debt.

The three full Figma contexts were read before implementation, and all 270 exports were verified. Shared cards, buttons, status words, native sheets and original exported icons supply the controls. The phone list retains the compact rows and draft card; desktop uses equal-height shared cards for the stock table and 400px supplier column, with footers pinned to the bottom; night count uses the supplied keypad/card layout. Phone controls have 44px targets and text on filled unit controls meets AA. Native device/browser chrome, later OCR, recipe deductions, purchase costs, cover predictions, remote agents and delivery tracking are omitted. Actual quantities and pack-rounded needs replace illustrative predictions. The Stock module loads separately and is precached for offline use.

The three visual comparisons use real onboarding, supplier forms, item forms and count controls. The quick-update capture shows a proposed change while rows retain their current values; the night-count capture is staged before Apply. No production data or fabricated completion state is inserted into the UI.

Local validation passes lint, TypeScript/Astro and the production build, 279 unit tests and all 133 browser tests. The fourteen new Stock scenarios cover reviewed/edited updates, rejected instruction text, stale reviews, offline counts/undo/reload, pack conversions, atomic variance batches, changed-item recounts, supplier copy/Sent/correction, archival/restore, large recommendations and optional speech without automatic writes. Stock, editors, count, summary, supplier handoff, supplier form and history fit and meet automated WCAG AA checks at 360, 390, 768, 1024 and 1440px. The full report completes 98 comparisons, including the three new references; pixel differences are informational and the captures were visually reviewed.
