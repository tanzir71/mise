# M32 desk controls and Inbox — in progress

The opt-in `kitchenAlarms` interface connects the existing notification journal to Notifications, Inbox and the order queue. The flag defaults off. It enables connection setup without enabling cloud sync, shared-screen mode or share capture. Corner-shop navigation keeps its existing Counter and Khata shortcuts; Inbox and Notifications are available from More.

## Browser choices and complete tasks

Opening a page never asks for notification permission. Enable starts the browser permission request directly in the click, then verifies the original native selection, phone account, connection and user choice before creating and saving the capability. An origin-wide Web Lock spans browser subscription replacement and the original journal commit. Only hashes enter the private local journal; raw endpoints and encryption keys remain in PushManager and the private server capability store.

Disable saves locally before any network cleanup. It keeps all cached tasks and original withdrawals, including an earlier setup whose SQL result is unknown. It works after an offline reload; reconnect and focus recheck phone authentication before retrying the original removal. A later Disable wins over an earlier permission dialog or held registration reply. An old warning-setting rejection stays unconfirmed without blocking an independent browser registration.

The isolated desk database upgrades to version 3 and profile wire version 2. It preserves existing profiles, pointers and original operations. A separate choice revision changes only for notification choices; a complete task refresh can advance the task cache while permission is pending without cancelling that choice or restoring older tasks. Native selection reads protect the brief private-cache writes. HTTP never holds a shop database transaction.

Inbox renders only complete, scoped kitchen-task reads. It shows actual Open order and Copy warning actions, with a selectable original warning if clipboard access fails. If the order has not reached this device, its target keeps the real warning accessible and offers Sync setup; it never invents a partial local order. A failed or partial read retains the last complete list and labels it as saved. The order queue uses those same task order IDs for a red line and warning words. Actual Got it closes the server task; the foreground desk then refreshes the complete list. These controls do not create an acknowledgement, change an order or record money.

Outlet warning settings remain separate from the queue’s ordinary late-order setting. Editing captures the original enabled/minutes/revision before asynchronous authorization. Rejected or unknown changes retain their original request and are never presented as confirmed. A fresh edit uses the currently loaded outlet revision; older unconfirmed actions remain in history for review.

## Background presentation and personal cleanup

The installed service worker accepts a closed generic kitchen-alarm payload. Before showing or opening it, the worker checks the actual native operator/setup, current private profile, enabled choice, original confirmed registration, selection pointer, subscription ID, expiration and hashes of the actual PushManager capability. It reads no owner token and makes no authenticated network request. Current server permission remains the delivery worker’s responsibility. A local lock, different account/outlet, replacement capability or Disable rejects the old notice.

The notification contains no customer text, order number, amount or URL. A click can only focus or open this installation’s Inbox. That page performs its normal authorization before reading records. A post-presentation check closes the exact old notice if the local choice changed during the browser await. A complete successful read also closes previously observed task generations that have resolved; unknown notices and absence in a failed or partial read cannot be treated as proof of resolution. An already in-flight provider send cannot be recalled.

Earlier notifications has an independent personal cleanup route, available while the native shop selection is locked. It shows generic saved-setup labels, can mute them offline and requires the actual original phone account/connection for the original HTTP withdrawal. Disposing that view closes its own SDK lifetime without signing out a different current view of the same stored account. It does not select an earlier outlet or alter the current shop records.
