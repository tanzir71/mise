# M37 · Native payment review preview

The default-off `ownerTasks` preview now opens actual observed payments from Inbox. **Add payment by hand** preserves the complete original source, reference, amount, currency, method, received time and optional sender phone. The original request is saved before HTTP. An observation creates an urgent task, with no sale, collection, khata entry or provider confirmation.

**Review payment source** opens its exact outlet and current source. **Check recorded receipts** reads a bounded page of actual eligible backend receipts, so the picker also works when this device has not downloaded those financial records. Current counter, paid-order and positive unreversed khata payments must match the source's amount, currency and literal method name. Claimed, reversed, wrong-outlet and inconsistent older order receipts are excluded. Older receipts use keyset paging; the page does not claim to be a frozen complete receipt catalogue.

Choose a receipt, inspect its actual amount, method, time and receipt number, then check the explicit confirmation. The app reads the selected receipt again before preparing the original match request. The transaction also rechecks actual source/target fingerprints, current membership and the unique financial association. A changed source or receipt requires another review. A forged or serialized object cannot supply the in-memory HTTP proof needed to prepare a choice.

If another person reviews the source while a dismissal reason is being typed, the live view retains that draft but clears old receipt choices and requires **Review updated source** before a new choice. Later automatic refreshes cannot silently rebind the draft to the newer source. The user's own confirmed receipt establishes the expected next version; historical receipts are still followed by a current source read.

Matching resolves only the source task and association. A subsequent financial change or reversal reopens urgent review, without rewriting the original match receipt. Dismissal requires a reason. **Withdraw observation** and **Undo last review** change metadata only; they do not reverse or restore money. When there is no receipt yet, one-tap links open the existing orders, customer ledger and counter flows to record the actual collection by hand, then return for matching. **Copy source** offers complete selectable text when the clipboard is unavailable.

Every pending review retains its complete source snapshot as well as its exact intent, chosen target and original IDs. Lost replies, offline reload, account/native changes, failed storage, stale views and competing writers cannot replace that original. **Check original result**, **Retry original request** and **Close original request** preserve its identity. Closure is written locally before HTTP; an offline reload retains the direction, and a delayed original submission cannot apply after confirmed closure. An older-role original may be inspected or closed with its original account but cannot silently submit under a new role. Saved receipts remain historical; current source facts are read separately.

**Saved payment requests from any outlet** opens `/settings/payments/recovery`, outside the selected operator's workspace and denied to paired shared-screen profiles. It enumerates only stable ownership metadata until the original phone account and target match. Recovery reuses a saved original SDK view or a separate installation-owned phone sign-in. Its private connection and Auth namespace are separate from both the selected operator and task recovery. Recovery cannot submit a new payment choice, read fresh source lists, select an operator or restore membership.

Full private copies work offline. Completed archival first verifies each actual immutable server receipt, then requires the exact downloaded file to be selected and read back locally before explicit removal. Only the completed prefix is removed; pending originals remain byte for byte. Source changes, another writer, damaged files, serialization, changed account/connection and failed storage invalidate removal. Nothing is silently evicted at the 200-entry/8 MiB limit. The private copy includes complete originals and receipts, with no SDK token or connection credential; it is separate from the shop's JSON backup.

Each installation supplies its own hosting, backend connection, phone sign-in, providers, credentials and numbers. No new provider or environment variable is needed for this review flow. Privileged provider settings stay in the installation backend. The manual capture origin stays `manual`; pasted text cannot claim verified provider status or select an executable command. No SMS, messaging or push request is sent by these controls or tests.

The receipt picker adds two scoped indexes and two guarded functions, with no direct table grant or new public definer. An independently recorded correction requires the candidate sale to be the exact receipt referenced by the current paid order; an older retained sale cannot duplicate or bypass it. Both applied migrations are frozen. All 489 pre-existing function definitions remain identical, both final candidate bodies match source, all 115 tables force RLS and the managed installation has 84 migrations/491 functions. The 63-check commissioning proof passes and rolls back all synthetic Auth/source/action records; the identical SQL bytes also pass locally. Advisers report no new warning or error. Existing Edge versions and empty Cron remain unchanged.

The design reference is M20 `103:900` with existing Inbox cards, type and review-sheet controls. Payment detail, capture, receipt confirmation and personal recovery are explicit operational additions beyond that phone frame. Comparisons report those differences; they do not assert pixel identity to sample task content. The preview remains off, and M37 still requires explicit general urgent notification choices, five-second delivery and resolution from its authenticated target. Existing kitchen subscriptions retain their purpose. Workflows, CI artifact upload, Pages publication and scheduling remain held by the owner.

The full unit invocation passes all 4,921 cases across 255 files. All 154 selected Pages-path browser cases pass in one invocation. Root-path coverage passes all 154 unique cases across the broad run and an eleven-case staff follow-up; the follow-up corrects an existing test that read its local closure before persistence completed. Earlier label and test-timing findings are retained in [the verification record](payment-sources-native-verification.json), together with source hashes, managed proof and the final lint, types, portable builds and 50 responsive comparisons. The comparisons report zero accessibility violations and horizontal overflows.
