# M37 · Personal saved task requests

The default-off `ownerTasks` preview now opens saved task originals independently of the currently selected operator. Use **Saved task requests** in Inbox, operator selection or onboarding. The `/settings/tasks/recovery` route is outside the active shop workspace and is denied to a paired shared-screen profile. Removing an outlet assignment therefore does not strand an unconfirmed original in that outlet's native journal.

Choose a saved group, then open its original phone account and shop connection. The initial group list reads only metadata keys; task sources remain closed until their original account and target hashes match. The original target binds the project origin, publishable key, deployment base, original business/discovery namespace and actual Auth user. A different project, key, base, user or unrelated SDK namespace cannot rebind it. Invalid or concurrently changing storage fails closed and retains all originals.

When its original saved SDK session is present, an independently owned view can open the local journal offline. Otherwise **Use a separate recovery sign-in** opens a dedicated SDK namespace. Its actual phone verification and local Forget affect only that recovery session. The recovery connection has separate private browser storage and can point to an older shop without changing the selected operator's connection. All connection details, SMS provider commissioning, service credentials and phone numbers belong to the installation and its users. No maintainer values are required. Phone numbers include their country code.

Recovery exposes only original inspection, closure, full private copy and completed-history archival. It cannot read a fresh outlet task list, submit a new task choice, select an operator, restore membership or change money. HTTP still requires fresh confirmed phone Auth. The server permits that same original user to inspect or close their own exact prior action after outlet removal. Closure is durably saved before HTTP; offline reload and reconnection retain the original action ID, complete source and closure direction. Unknown closure fences a delayed submission. Another current account stays signed in, and leaving recovery disposes its view without logging out another SDK client.

**Save full private copy** works offline after local original-account continuity is established. It includes every saved source, reply, receipt and pending closure. It deletes nothing and contains no SDK session or credentials. It is separate from the shop's JSON backup because these originals belong to the individual phone account.

The normal source view shows the complete task details, prepared message, recorded replies, recipient, author and saved time. Internal IDs and receipt structures stay in the private download rather than filling the recovery card.

**Save completed archive** inspects every completed original against its actual immutable server receipt. Only the completed prefix is included. The user saves that private file, selects the saved file locally, and explicitly chooses **Remove verified completed copies** after its full bytes match. File selection is a local read, with no upload. The original journal is retained if any inspection, hash, storage write, current-account proof, original snapshot comparison or final confirmation fails. A forged/serialized plan and an altered file cannot authorize removal. Another tab's changed or appended original invalidates the plan. The pending original stays byte for byte in the journal. Shop tasks, server history, orders and financial records are unaffected by local archival. There is no silent eviction at the existing 200-entry/8 MiB limit.

The recovery controls reuse the M20 `103:900` Inbox cards, type and existing setup primitives; account selection and saved-file verification are explicit adaptations beyond that phone reference.
