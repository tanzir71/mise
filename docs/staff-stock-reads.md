# M34 · Staff stock read prerequisite

The backend now connects the outlet's actual **Update stock** choice to a restricted current-stock reader for an enrolled device and its own PIN member. This is the read prerequisite for the staff quantity flow. Reviewed quantity changes, durable original requests, closure/undo and the shared-screen stock interface remain unfinished. M34 stays unchecked. The `staff-stock` service is undeployed and disabled by default, and workflows and publication remain held.

## Current scope

Eligible desk staff can read stock on either supported screen mode. Kitchen staff can read it on a kitchen screen. Riders and kitchen members using counter attendance retain their existing attendance-only boundary. No old stock grant is inferred: the current outlet Team profile must explicitly enable `updateStock`, and an existing individual `stock.read` value other than true still denies reading. Another outlet's profile cannot grant access. Preparation and attendance keep their separate permissions.

The service-only RPC derives the business, outlet, device, session and member from the actual device/PIN credentials. A caller cannot select a different member or outlet. It checks current assignment, activity, PIN revision, revocation and actual expiry, serializes with the outlet's mutations, and rechecks after acquiring locks. Same-statement expiry is checked against the real clock. A per-device/server-minute budget spans that screen's PIN sessions.

Keyset pages contain at most 100 active items, in distinct ID order, with a checked continuation. They also respect the existing 50 MiB backup byte limit, retaining whole items; a nonempty short page continues from its actual last item. The service transport allows 64 MiB for the complete envelope. They include only visible labels and aliases, unit/category, on-hand/target/pack/low quantities, revisions, count metadata and item timestamps. Supplier contacts, purchases, prices, customers, money, source notes, owner Auth and private service credentials are excluded. Native JSON output retains existing Bengali names, control characters and surrogate source without JSONB decoding or an extra layer of quoting. PostgreSQL documents these [JSON Unicode restrictions](https://www.postgresql.org/docs/current/datatype-json.html). Quantity validation keeps the existing integer-thousandth arithmetic limits. A structurally valid page never authorizes a write or establishes current access after a later denial.

The HTTP handler rejects extra selectors, mutation operations, credential queries, foreign origins, malformed sessions and oversized/slow bodies before calling its fixed RPC. It checks the whole returned page and closes failures with generic messages. The service transport bounds response bytes and the entire request lifetime, including a body that ignores abort. Supabase's [function authorization headers](https://supabase.com/docs/guides/functions/auth-headers) and [database function privileges](https://supabase.com/docs/guides/database/functions) inform the private-key header, custom device authentication and service-only grants.

## Installation configuration and fallback

Each installation owns its connection, device pairing, member PINs and private backend settings. `MISE_STAFF_STOCK_ENABLED=false` keeps this independent service unavailable. `MISE_STAFF_STOCK_REQUESTS_PER_MINUTE` is optional, accepts integers from 1 to 60,000 and defaults to 600. It reuses the installation's server-side service key and exact origins. Empty templates contain no project, organization, credential value or personal receiving number. No maintainer account, phone or verification code is required.

Keep this service off until the intended installed preview is ready. The existing owner/assigned-manager stock flow and telling the manager by hand remain usable. A staff quantity request will need its own actual authorization, complete review/source and durable recovery; neither this read capability nor a copied Team switch substitutes for it.
