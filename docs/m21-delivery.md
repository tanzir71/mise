# M21 · Paste to order

Status: in progress. The pure parser and twenty real-style fixtures are implemented. The Orders paste interface and reviewed hand-off to the existing order/pricing forms are still required. No new interface is enabled and M21 remains unchecked.

`parsePastedOrder` recognises the complete M20 envelope using its existing bounded parser. It preserves customer/fulfilment/time fields, photo intent and payment preference as untrusted proposals. Unknown or damaged Mise formats keep every nonempty line literally for manual review, without extracting their purported headers. Free text recognises only explicit English/Bangla contact/fulfilment/time/payment labels and a complete bare phone number. Duplicate or invalid headers remain literal lines. Original source text, line spacing and unknown notes remain available; nothing executes customer instructions.

Explicit leading counts, `×`/`x` counts, trailing `x` counts and supported weight/volume/count units produce editable suggestions. Bengali digits are accepted; medication strengths, fractions and ambiguous or out-of-range quantities stay literal. No prices, catalogue IDs, paid state, order status, scheduling action or database write is inferred. Relative times remain text for owner review. The parser rejects over 12,000 characters or 200 nonempty lines instead of silently truncating.

The twenty fixtures cover English, Bangla, mixed scripts, decimals/units, contact labels, pickup/time, delivery, medicine strengths, fractions, markup, instructions and CRLF. Additional cases cover complete EN/BN M20 messages, damaged envelopes, duplicate/invalid headers, claimed payments and size/quantity bounds. UI integration must preserve complete M20 source messages beyond M14's current 4,000-character source-note limit; it must not truncate them to make an order save pass. The source-note/editor/backup bounds will be updated together in that increment.

Foundation verification: all 27 new parser cases and all 399 unit tests pass. Lint and TypeScript/Astro diagnostics pass. The production build passes. The full browser run passed 205 cases and exposed one fixture timeout: a forced navigation to More occurred during worker activation, after every precache resource returned HTTP 200. The fixture now clicks the actual More link, preserving the activating client; all eight Shop link cases then passed three repetitions (24 checks), without retries or larger timeouts. Full CI evidence follows the push. The existing M20 interface and public offline resource set are unchanged by this unreferenced domain module.
