# M18 · Installation, offline launch and local storage

Status: in progress. The manifest and install/storage interface are implemented. Full regression, visual report, CI, published installation checks and the Phase 1 release are pending. M18 remains unchecked.

The app has a stable identity, start URL and scope under the configured app base, including `/mise/app/` on Pages and `/app/` for a root deployment. It uses the ink theme, standalone display, a 192/512px raster mark, full-bleed maskable icon and Apple touch icon generated from the original supplied Mise SVG. The manifest and icons join the offline precache. The local preview serves the manifest with its correct MIME type.

Installation guidance is available before the three onboarding questions and from More › This device. A browser install offer is captured at startup; a tap invokes it once. Dismissal and errors keep the manual steps. An accepted prompt is described as requested until the browser confirms installation or the app launches standalone. Safari home-screen apps have separate local storage, so an existing shop gets explicit full-backup/restore instructions, while a new shop can install before setting up. See [WebKit's documented behavior](https://webkit.org/blog/14787/webkit-features-in-safari-17-2/).

This device shows offline readiness only once a worker controls the page. The existing update prompt preserves open forms until the requesting tab explicitly reloads; the real-worker test also preserves another tab's draft. Manual checks report offline/network failure without navigation. Storage protection reads the browser's actual state and requests persistence only after a tap. Granted, denied, unavailable and failed requests retain a working complete JSON backup fallback; business data does not change.

M18 specifies no dedicated Figma frame. Its interface reuses M27 More rows, existing settings cards, supplied icons and tokens, 44px phone targets, and equal-height desktop cards. Three reference comparisons cover More on a phone and This device on phone/desktop. Content differences from the later-phase reference remain informational.

The handover's Lighthouse PWA criterion is obsolete: [Lighthouse 12 removed that category](https://github.com/GoogleChrome/lighthouse/blob/v12.0.0/changelog.md#pwa-category-removal). Verification uses the actual parsed manifest, Chromium installability errors, decoded raster dimensions and a persistent full-Chromium profile. That profile closes, reopens the saved shop offline and records another sale. This verifies installability and real offline relaunch, without claiming a physical Android/iPhone install or a retired Lighthouse score.

Focused checks pass: all 14 new browser cases, TypeScript, lint and the production build. Chromium reports no installability errors. Native prompt outcomes and standalone detection, iPhone instructions, all storage outcomes and manual backup, and five-width axe/overflow/card-height checks pass.
