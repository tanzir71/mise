# Accepted payments keep their exact original on another device

M41 now retains complete immutable payment originals under the outlet before the actual SDK controller sends a financial command. The pending source comparison is serialized with native action acceptance; an accepted action creates its source locator in the same transaction as money, history and the genuine native receipt. Losing the financial reply or deleting the uploader before it arrives cannot leave that accepted action without its retained source. A locator failure rolls the financial transaction back. The original command remains available for one genuine retry.

Five private, forced-RLS tables hold retained copy descriptors, shared literal nodes, exact copy membership, nonauthoritative pending comparisons and accepted source locators. Identical nodes are shared within one outlet. No Auth account or session is a parent of this durable outlet archive. Promotion copies only a completed personal content graph, compares complete membership and bytes, and enforces the bounded copy/node budget atomically. Personal-copy cleanup does not erase the outlet archive. No client or service-role table grant is added.

The existing authenticated original-copy endpoint gains explicit payment retention, staging, inspection and bounded read operations. Its new protected RPC checks the actual phone account, live Auth session, current database member and outlet authorization before body consumption and again before completion. Private helpers and triggers are invoker-only; the new private definer function is the deliberate privilege boundary, behind an authenticated invoker wrapper. It executes no financial command. The existing native financial algorithms, command identifiers and retry receipts stay unchanged. A pending comparison alone cannot create a command or an accepted result.

The response names the actual current reader separately from the copy origin. The real SDK controller checks this identity on every operation and multipart response. A manager keeps their own identity while reading an earlier owner's source; an origin label never supplies the manager's role. The fresh-device reader verifies every node hash, exact membership, byte count, original manifest and complete portable archive. A separate Core comparison checks the actual accepted invocation and native receipt against the strict original action and financial history; callers must obtain that accepted result from the verified native download. The reader does not infer acceptance from an archive. It neither installs domain records nor creates outgoing work. Interrupted reads can restart from the immutable locator; durable native installation and connected restore remain separate M41 requirements.

The historical-owner copy capability remains separate. Revoking current outlet access denies the shared read path without rewriting existing personal ownership or granting new financial rights. Current role and session checks apply to each new read; a copied archive, locator, storage receipt or serialized reader label is evidence only.

Accepted locators enter the same bounded snapshot stream as native observations, audits, outcomes and financial rows under `native_payment_originals`. They expose public domain IDs and immutable hashes, never Auth UUIDs, session IDs, tickets or credentials. Whole-original validation is required in addition to row-level decoding. The native canonical installer remains fenced, including tombstones, until full original-versus-current financial reconciliation is implemented. Older accepted actions receive no fabricated source links; registering genuine historical originals remains explicit work.
