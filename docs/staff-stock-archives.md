# Verified stock archives

The shared-screen stock history can now save complete recorded or closed originals, verify the saved file and explicitly remove its local copies. Reopening that exact file retains a path to own-original recovery and undo. This extends the [stock interface](staff-stock-interface.md) and [native journal](staff-stock-native.md). Full M34 acceptance remains open.

## Save, verify and remove

Open My requests and choose Save completed stock archive. The screen first inspects each selected original through its actual own-device/PIN backend route and requires the same terminal outcome already retained locally. Preparing an archive changes no quantity and removes nothing.

Select the file your browser saved. The app reads every byte and checks its SHA-256 against the prepared archive. A wrong file or a later failed selection invalidates verification. Only Remove verified stock copies removes the completed prefix. Unconfirmed originals, read denial and original source remain intact. Another tab, changed enrollment, sign-out, storage failure or stale native revision stops the write without dropping history.

The native transaction retains a fingerprint receipt for the exact file at the same time as it removes those completed copies. Fingerprints are scoped to the original backend connection and enrolled-device secret, plus the actual business, outlet, device and member. The index holds hashes and counts; it contains no provider credential or file source. Existing version-four screen stores remain intact, and ordinary history replacement still cannot delete or import records.

Each original keeps its existing 50 MiB budget. Each archive file holds up to 64 MiB of complete originals. If another whole original will not fit, it remains on the screen for the next file. There is no clipping, history eviction or smaller aggregate journal budget. At 200 saved originals, this verified flow can free space; manual manager handoff remains available. Fingerprint receipts are retained rather than silently evicted.

## Reopen and recover

Open a stock archive selects a local file for the current member on its original enrolled screen. Complete source can be viewed and copied offline. The app labels it historical; it never uses it as current stock or permissions. A reformatted or edited file has no matching fingerprint and cannot restore history. Keep the original downloaded bytes. If the browser profile or enrollment is replaced, retain the file for manual recovery; it does not carry a sign-in or enroll another device.

Check and restore original requires both the retained exact-file fingerprint and a fresh actual own-original backend receipt. It restores the original request, physical time, IDs, close choice and immutable outcome without submitting a stock change. A pending request remains the last pending original, and known read denial stays denied. A later own PIN can recover an earlier original even after work permission is removed. Another member or backend cannot inherit the archive receipt.

The restored original exposes the existing own undo path. Undo still needs a newly returned quantity page, its real original movement receipt, a current comparison and explicit confirmation. Existing backend time/count/withdrawal rules continue to apply. Restoring a file alone never changes stock or money.

## Manual paths and installation

Download archive again and Copy archive text keep the complete file available if saving fails. Clipboard failure exposes a selected readonly field for manual copying. Keep copies here cancels the plan without changing history. Copy complete original, Copy archived original and the manager handoff remain available independently of quantity work.

This adds no account, credential, provider, phone number or configuration input. Every installation owns its existing hosting, backend connection, enrolled devices, PINs and private service settings. No managed migration, service deployment or provider request is added. Both stock services remain disabled/undeployed; preview flags, workflows, CI uploads and public deployment remain held.
