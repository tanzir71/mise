# M17 delivery in progress

M17 covers Orders, Sales, Credit, Stock moves, Customers and Purchases exports in CSV/XLSX/PDF, date ranges, and full JSON backup/restore. The milestone remains unchecked until its interface, file formats and published end-to-end flows pass delivery.

## Backup foundation

The first increment adds consistent read transactions across all nineteen existing tables at schema 7. The versioned `mise-backup` envelope contains every table, including audit events, notes, communications, refunds, stock/supplier history and immutable day-closing snapshots. JSON preserves original IDs, integer minor-unit money, E.164 phones and Bengali text. Optional undefined object fields are omitted using JSON semantics. An empty new browser can be compared; an empty file cannot replace a configured shop.

The dry run validates the complete schema, required tables, safe money/timestamps, supported enum values, phone formats, duplicate primary/compound keys, live cross-record links, credit reversal effects, stock quantities/history and closing/receipt links. Immutable historical catalogue lines may retain deleted item IDs. Unsupported schema versions or fields are rejected explicitly; data is never silently discarded. Files above 50 MB are rejected before parsing.

Restore replaces the local shop in one read/write transaction. Exact canonical source and current-data tokens bind the preview to both the selected file and every local record; table iteration order and the capture time of the current browser snapshot do not create false conflicts. A changed record with the same table counts still invalidates the review. Concurrent confirmations restore once. Import failures, including failure of the final audit write, roll back all clears and imports. The audit records the source timestamp, before/after counts and the previous local owner when available, using a system actor rather than attributing a different shop’s action to the imported owner.

Backup code is loaded on demand before opening the IndexedDB transaction. No database migration or user-facing route is introduced in this increment. CSV/XLSX/PDF, sharing, restore confirmation and reference-based phone/desktop UI follow in the next increments.

Validation so far: nine real-Dexie/fake-IndexedDB tests populate all nineteen tables through domain commands, including bilingual notes, deleted catalogue snapshots, cancelled cash/credit orders, refunds, payments and reversals, supplier drafts, stock counts/undo and two closing snapshots. A fresh database restores every source record unchanged, adds one restore event and reproduces identical Today and credit totals after reopening. Additional cases cover replacement, stale reviews, changed files, concurrent confirmation, invalid files, atomic rollback, historical currencies, zero-total orders and archived contacts/stock. ## Report and invoice foundation

All six M17 datasets project actual records from one validated backup snapshot. Sales retain cancelled/undone originals and separate refund rows; net-sales and physical-cash columns avoid subtracting cancelled amounts twice. Credit statements calculate balances from the full ordered ledger before applying the selected date range. Stock movements retain counts, reversals and original units. Customer balances retain each account’s currency. Column and record selection are supported, phone fields are masked by default, and full JSON backups retain the original data.

Purchases use priced invoice records, not received-stock movements. Additive schema 8 adds `purchases`; recording or undoing an invoice is audited and atomic. Recording an invoice does not assert that its stock has been received, settle supplier credit or change the counter cash box. The later capture phase will compose invoice/receiving actions. No invoice-entry or capture UI is introduced here. Existing shops have zero purchase rows until invoices are recorded. Schema-7 JSON files upgrade by adding an empty purchase table; all nineteen original native IndexedDB tables remain unchanged during migration. JSON restoration retains JSON semantics for undefined fields and negative zero.

Today/week/month/custom ranges use civil dates in the outlet timezone. Weeks begin after the configured market weekend (Sunday in Bangladesh, Monday for the other current packs). Custom dates include their whole ending day, including daylight-saving changes. Customer date ranges use the date added; exported customer balances are current.

CSV uses a UTF-8 BOM, quoted fields and CRLF rows, preserving Bengali and multiline notes. Text that could be a spreadsheet formula is escaped; real signed monetary values remain numbers. XLSX cells store text literally, retain ordinary numeric cells for calculations, and preserve amounts exceeding Excel’s 15-digit precision as text. CSV preserves those large amounts as text too. Each workbook includes a Read me sheet with shop, period, timezone and accounting notes. The unmodified Apache-2.0 SheetJS 0.20.3 tarball is vendored with its checksum and official source; the on-demand wrapper keeps it out of the app shell and never loads a CDN script at runtime.

The new tests cover all datasets, refunds/reversals, historical currencies, precise invoice rounding, failed-write rollback/undo, schema-7 migration/restore, calendar and daylight-saving boundaries, Bengali CSV reopening, literal customer formulas and exact large XLSX amounts. UI integration, PDF report layout, native sharing and the three M17 visual captures are still pending.
