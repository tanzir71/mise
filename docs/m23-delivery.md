# M23 · Shared message hand-off

Status: durable foundation and three staged owner adapters implemented. Credit reminders/receipts/calls, priced orders/calls and supplier drafts use the shared component when `handOffs` is enabled. It remains off by default; other outbound senders and the milestone acceptance checkbox remain open.

`packages/core/handoff-progress.ts` is a browser-independent protocol shared by the owner and the small public customer page. Open and Copy never imply delivery. Clipboard denial and Didn't work remain unconfirmed; only explicit Sent records confirmation and its channel. Later Copy/Open choices preserve that confirmation. Undo removes only the local sent mark, within ten minutes, and restores the latest attempt, including same-timestamp failures or reopened apps. It cannot recall an external message.

The protocol preserves immutable input, strict serialisable state, timestamp-zero confirmations and monotonic revisions. It rejects unsupported choices, forged state, invalid times and revision overflow. Seventeen unit cases pass, including 700 serialised intermediate states. Lint and TypeScript checks pass. Its standalone minified gzip size is 1,178 bytes; this is not the customer's actual integrated resource budget.

Remaining implementation: integrate the other outbound messages (cash receipts, closing summaries, shop links/poster copying and manual win-back), the public customer's small adapter, complete regression/visual verification and enable the shared interface. The data foundation adds audit indexes as described below. M22's physical device acceptance remains pending while this independent Phase 2 work proceeds.

The durable owner foundation reuses the audit-event table. Schema 9 adds `handoffId`, `handoffTopic` and a unique `[handoffId+handoffRevision]` index; all twenty existing tables and their records remain intact. Backups from schemas 7 and 8 normalise into schema 9. Original drafts retain literal whitespace, Bangla, parts, destination and text; subject ownership is checked against the current shop. An unchanged latest draft resumes; edits or an explicit new attempt create another generation. Every Open, Copy, failure, Sent and local undo appends a validated before/after snapshot. Revision guards reject concurrent forks; retrying an action ID returns current progress without adding an event or rewinding subsequent choices. A backwards device clock is normalised at the storage boundary.

The staged shared component now serialises draft saves and choices, invokes clipboard/share/deep links from the initiating gesture, provides a manual field after failure and keeps an explicit Sent confirmation. Credit, order and supplier completion runs atomically with that confirmation, so a stale order or failed final audit cannot leave partial companion history. Reopening an unchanged source restores owner edits and progress; changed source templates/destinations prepare a fresh reviewed generation. The nested attempt format is version 2 when an explicit template is present; version-1 history and schemas 7/8/9 backups remain readable without another database migration.

A tab-scoped pending-edit cache bridges the short delayed-save window and is cleared after IndexedDB commits the exact text. Closing and immediately reloading therefore retains an edit; ordinary resumption and backups use the durable audit history. Calls retain an explicit manual fallback. Reopening a confirmed attempt offers Done and Start another attempt; Done does not write another business communication. A later failed copy retains the earlier Sent mark and still exposes manual selection. No shared Undo control is exposed while companion-correction semantics remain separate.
