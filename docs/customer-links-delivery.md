# Customer links · owner controls and customer reads

Status: **verified increment; M30, M33 and M35 remain open**. `customerLinks` is off by default. GitHub workflows, Pages publication and the product scheduler remain held by the owner.

An owner or assigned manager can create an order or khata link from its existing detail page, copy it, prepare an English or Bangla message, open WhatsApp and explicitly mark the hand-off done. Existing manual messages remain available. A scoped list includes links created on other devices, including legacy, revoked and expired links. Listing returns metadata only and does not change financial records or write an audit event.

The original issuance and closure identities are saved before delivery. A lost reply or reload retains that attempt without inventing another grant. The secret exists only in memory; after reload the operator inspects and explicitly closes the original before replacement. A late original request cannot reopen a closed attempt. Retries preserve the actual first closure, even when another authorized person completed it. A pending legacy revocation retains its original event. Account, installation, operator, resource, outlet and journal changes invalidate the in-memory link.

Customer routes `/app/t/<token>` and `/app/k/<token>` load without an account or owner database. They show the existing order's actual status, business-pack steps, items, integer prices and payment record, or the customer's balance and paginated ledger. English and Bangla are available. A scheduled preparation time is labeled separately; there is no invented arrival estimate, delay notice, earlier status time, wallet destination, payment or task. The approved public shop snapshot supplies contact details; private customer and Auth phone numbers are not used. Call/message actions include Copy and a manual completion action. An unavailable contact directs the customer to the original chat.

Each installer enters its own public backend connection through Sync setup. Generated links carry only the customer capability and public API origin, with that origin in the URL fragment. They contain no publishable key, owner JWT, service credential or tenant/member identifier. HTTPS is required except for local loopback testing. The customer reader sends a fixed, uncached, credential-free request with no referrer, bounded response size and a complete request deadline. Data is not persisted to localStorage or IndexedDB. Revocation removes the data on the next read; an unavailable link stops background reads. The installation's existing server budgets apply.
